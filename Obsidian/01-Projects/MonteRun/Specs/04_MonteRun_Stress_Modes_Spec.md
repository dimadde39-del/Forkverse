Назначение. Этот документ описывает одну конкретную функцию продукта MonteRun и фиксирует её цель, логику, интерфейс, правила, метрики и границы реализации для MVP.

1. Цель функции

Показать, насколько базовый план хрупок при одном узнаваемом ударе. Именно здесь Monte Carlo и сценарное моделирование дают отличие от обычного калькулятора.

2. Дизайн-принцип

Stress modes должны звучать как жизнь, а не как учебник. Пользователь должен мгновенно узнавать ситуацию и понимать, почему она опасна.

3. Набор stress modes MVP

Режим

Описание

Bad Month

Общий плохой месяц: рост расходов и просадка дохода.

Late Payments

Ключевой клиент задержал оплату.

Client Loss

Один источник дохода исчезает.

Emergency Expense

Внезапный крупный расход.

4. Логика интерфейса

• Stress mode должен включаться одним кликом.

• Сравнение с base mode должно быть мгновенным.

• Пара цифр Base vs Stress должна считываться без текста.

• Пользователь должен уметь переключать stress mode без повторного ввода всей анкеты.

6. Guardrails

• Не плодить 20 режимов на старте.

• Не использовать абстрактные названия.

• Не превращать stress mode в драму ради драмы. Всё должно опираться на числа.
