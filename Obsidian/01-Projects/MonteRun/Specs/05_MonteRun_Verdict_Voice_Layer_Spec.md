Назначение. Этот документ описывает одну конкретную функцию продукта MonteRun и фиксирует её цель, логику, интерфейс, правила, метрики и границы реализации для MVP.

1. Цель функции

Упаковать сухую математику в управляемый стиль вывода, не ломая доверие и не превращая продукт в дешёвый roast-бот.

2. Правило разделения

Tone layer никогда не меняет цифры, ranking levers или stress outputs. Он получает только structured result и формирует текстовую подачу.

3. Tone modes MVP

Mode

Правило

Brutal

Коротко, жёстко, вирусно. Подходит для X/Twitter и Telegram.

Cold

Сухой терминальный стиль без театра.

White-label

Нейтральный вывод для API и корпоративного контекста.

4. Verdict policies

• Никаких выдуманных цифр.

• Никаких инвестиционных советов.

• Praise discipline: сильный сценарий должен быть признан, а не искусственно высмеян.

• Output должен быть коротким и легко помещаться в share-card или summary block.

5. Примеры поведения

Сценарий

Ожидаемый стиль

Критический runway

Прямой и холодный вердикт без паники.

Хрупкий, но поправимый сценарий

Указать уязвимость и сразу показать leverage path.

Сильный сценарий

Сдержанная похвала без лести.

6. Запрещённое поведение

• Клоунские шутки и мемный тон.

• Унижение ради комедии.

• Нечёткие формулировки вроде “кажется” или “возможно”, если математика уже посчитана.
