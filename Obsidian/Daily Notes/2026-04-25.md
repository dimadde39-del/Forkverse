# 2026-04-25

## MonteRun income delay validation

Validated the `income_delay_months` rollout as the fourth/final ParanoidValidator pass.

Scope audited:
- `engine/monte_carlo.py`
- `api/parse.py`
- `api/simulate.py`
- `prompts/parser_v1.txt`
- `components/SimulatorClient.tsx`
- `components/WhatIfControls.tsx`

Canonical constraints applied:
- MonteRun remains a deterministic survival engine, not an AI probability engine.
- LLM parsing can extract `income_delay_months`, but the NumPy core owns all math.
- `income_delay_months` defaults to `0` for old links and old parser payloads.
- Delays greater than the simulation horizon must not crash or index out of bounds.
- Delay handling must stay vectorized, not loop over months inside the simulator.

Audit findings:
- `MonteRunParams` carries `income_delay_months: int = 0`.
- `_simulate_capital_paths(...)` now applies income timing through the `TimeMasks` layer.
- `_build_time_masks(...)` clamps delay to `[0, months]` and builds an `income_active` NumPy mask from `np.arange(months)`.
- Realized income is multiplied by the mask through NumPy broadcasting; no Python loop over months was introduced.
- If `income_delay_months = 3`, income in simulated months `0`, `1`, and `2` is inactive for every path.
- If delay exceeds horizon, all income columns are inactive without out-of-bounds access.
- Parser prompt includes the required instruction: "Extract how many months the user will wait before their first revenue. Default is 0."
- Parser normalization defaults missing delay to `0`, preserves explicit integer delay, and forwards it into `MonteRunParams` and legacy `simulate(...)`.
- `/api/simulate` normalizes `income_delay_months` to a non-negative integer with default `0` before calling the engine.
- What-If UI clamps delay controls to `0..12`, step `1`, with the label `Задержка дохода (мес)`.
- Existing debounced recalculation path is preserved through `useDebouncedSimulation`.

Validation commands:
- `python -m py_compile engine\monte_carlo.py api\parse.py api\simulate.py` passed.
- Focused Python invariant checks passed:
  - omitted delay equals explicit `0`
  - three-month delay keeps first three simulated income months inactive for every path
  - over-range delay clamps to the horizon and does not crash
  - API default is `0` when delay is absent
  - API rejects negative, boolean, fractional, and non-numeric delay values
  - `compute_metrics(...)` remains JSON-serializable and keeps sampled paths bounded
- `npx tsc --noEmit` passed.
- `npm run build` passed on Next.js 16.2.3 / Turbopack.
- `git diff --check` passed for the implementation files, with CRLF normalization warnings only.

Edge cases covered:
- Missing parser delay field defaults to `0`.
- Explicit parser delay propagates through normalized params.
- Clarification state does not ask only because delay is absent.
- Delay greater than horizon is safely clamped to available matrix columns.
- Delay greater than the legacy 24-month simulation horizon is accepted by the Python API and handled in the core.
- Frontend What-If control remains intentionally bounded to `0..12` for user-facing scenario adjustment.
